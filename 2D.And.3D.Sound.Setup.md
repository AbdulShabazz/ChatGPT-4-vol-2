**Q: In Unreal Engine Blueprints, how do I add a 2D sound and a 3D sound to a level actor?**

**A:** Add them as `Audio Component`(s) on the actor, then configure each component for “2D” (non-spatial) or “3D” (spatial/attenuated).

2D sound on a Level Actor (non-spatial)

1. Select the actor in the level.
2. In the Details panel, click **Add Component** → **Audio** → **Audio Component**.
3. In the new Audio Component’s Details:

   * Set **Sound** to your `Sound Wave` / `Sound Cue` (or MetaSound Source).
   * Disable spatialization:

     * Set **Allow Spatialization** = false (or **Spatialization** off, depending on version).
   * (Optional) For UI-like behavior, set **Is UISound** = true.
   * (Optional) Set **Auto Activate** = true if you want it to start when the level begins.
4. If you want explicit Blueprint control, call `Play` / `Stop` on that Audio Component (e.g., in `Event BeginPlay`).

3D sound on a Level Actor (spatial)

1. Select the actor in the level.
2. **Add Component** → **Audio Component** (a second one, or reuse the first and switch settings).
3. In the Audio Component’s Details:

   * Set **Sound** to your asset.
   * Enable spatialization:

     * **Allow Spatialization** = true.
   * Set attenuation (this is what makes it “3D” in practice):

     * Assign an **Attenuation Settings** asset (recommended), or enable **Override Attenuation** and configure:

       * **Attenuation Shape** (Sphere/Capsule/Box/Cone)
       * **Falloff Distance**
       * **Inner Radius**
   * (Optional) If you want directionality, use a Cone attenuation shape and set cone angles.
4. Position matters: move the Audio Component relative to the actor (Component transform) if you want the sound source offset from the actor origin.

Minimal Blueprint wiring (if you want both to start on BeginPlay)

* In the actor Blueprint:

  * Components: `Audio2D` (Audio Component), `Audio3D` (Audio Component)
  * Event Graph:

    * `Event BeginPlay`

      * `Audio2D -> Play`
      * `Audio3D -> Play`

Notes

* “2D” means “not spatialized.” It will not pan/attenuate with distance.
* “3D” typically means spatialization + attenuation (and optionally occlusion).
* For ambient loops in a level, also consider `Ambient Sound` actors, but Audio Components on your Level Actor are the most direct “add to this actor” approach.

**Q: Explain the optional UI setting within the audio component.**

**A:** **Result:** The **Is UISound** flag marks an Audio Component as user-interface audio, changing how it is mixed, routed, paused, and spatialized.

**Behavior when Is UISound = true**

* **Non-spatial by definition:** Treated as 2D. Spatialization and attenuation are ignored.
* **Pause immunity:** Continues playing when the game is paused (`Set Game Paused = true`).
* **Mix routing:** Routed through UI sound classes/mixes (commonly a dedicated UI bus).
* **Listener-independent:** Not affected by listener position, rotation, or world location.
* **Priority semantics:** Often higher priority to avoid being culled under load.
* **Platform conventions:** Respects platform UI volume sliders when configured.

**Typical use cases**

* Menu clicks, confirmations, alerts.
* HUD feedback (inventory open/close, notifications).
* System prompts that must be audible during pause screens.

**What it does *not* do**

* It does not automatically play the sound.
* It does not apply UI compression/EQ unless your Sound Class/Mix defines it.
* It does not override concurrency rules unless configured elsewhere.

**Recommended configuration**

* Set **Is UISound = true**.
* Assign a **UI Sound Class** (e.g., `SFX_UI`) with appropriate volume scaling.
* Disable spatialization explicitly if exposed (defensive).
* Avoid attenuation assets on UI sounds.

**Common pitfalls**

* Using Is UISound for in-world sounds you want audible during pause. Instead, keep it non-UI and manage pause behavior explicitly if spatial context matters.
* Forgetting to route UI sounds to a separate Sound Class, causing global SFX volume changes to affect UI unintentionally.
